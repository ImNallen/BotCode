# UI baseline

Bot Code renders the T3 Code interface for every workflow it implements. The reference is T3 Code v0.0.45 (`pingdotgg/t3code` tag `v0.0.45`, commit `6c8fed35d`), the build in the installed desktop app. T3 Code is MIT licensed. Ported files name their source in a one-line header.

## Styles come from T3, not from a lookalike

`src/t3-theme.css` is T3's `apps/web/src/index.css`, copied verbatim. Regenerate it with `scripts/port-t3-theme.sh <t3code-checkout>`. Tailwind v4 compiles it through `@tailwindcss/vite`, so components use T3's own utility classes and tokens: `bg-sidebar`, `text-secondary-label`, `--chat-max-width`, `alert-glass`. `src/styles.css` imports the theme and holds the only Bot Code overrides: root typography, which T3 sets from JavaScript, and the macOS traffic-light inset.

`src/ui/controls.tsx` copies T3's `buttonVariants` and `toggleVariants` tables and the select trigger and item classes. Components copy T3's class strings literally. A hand-written approximation drifts the first time T3 changes a token. A copied class string can only drift when the copy is stale.

## Layout

The shell matches T3's desktop app:

- A 256px left sidebar, resizable from 208px and collapsible with Command+B. It holds the brand row, thread search, T3's project filter, **Add project**, **New thread**, and T3's Pinned section, Active list, Snoozed shelf and Settled shelf across every repository. Pinned threads show as cards at the top, newest pin first. They have no header, because T3 labels them only while dragging. The pin icon on a pinned card unpins it. Active threads show as cards below them, newest activity first. Hovering a card shows a clock button and **Settle** in place of its time, except while an approval waits. The clock opens T3's snooze presets: In 1 hour, In 3 hours, This evening while 6 PM is more than an hour away, Tomorrow at 9 AM, and Next week on Monday at 9 AM. Right-clicking any thread opens T3's thread menu with Pin or Unpin, Settle or Un-settle, and a Snooze submenu with the same presets, or Wake when the thread is snoozed. The **Snoozed** shelf appears above Settled while any thread is snoozed. Its slim rows show the soonest wake first, the time left, such as "2h", and a **Wake thread now** button on hover. It starts collapsed as "Snoozed (n)" and shows only the open thread's row until expanded. A snoozed thread comes back when its wake time passes, without a reload. It comes back early when an approval arrives, or when a turn completes or fails after the snooze. A pinned thread keeps its pin while snoozed and comes back into Pinned. The **Settled** shelf sits at the bottom of the list as slim rows, most recently settled first, with a dimmed badge, the title, the settled age, and an **Un-settle** button on hover. It starts collapsed as "Settled (n)" and shows only the open thread's row until expanded. Expanded, it shows 10 rows and then **Show more** in steps of 25. Both shelves remember their state on this device. Search shows every matching snoozed and settled row. Settling or snoozing the open thread opens the next card, or a new draft in its project when none is left. Command+Shift+S settles or un-settles the open thread in place, and Command+Shift+P pins or unpins it in place. Pinning clears a settle or a snooze. Settling clears a pin or a snooze. Snoozing keeps the pin or settle. A thread settles by itself after its project's auto-settle limit without activity, 3 days by default, unless the user un-settled it or it is snoozed. An idle pinned thread settles by itself too and loses its pin, as in T3. Pinning a settled thread un-settles it, so it stays pinned until its next activity and does not settle by itself before then. A new prompt clears the snooze and returns a settled thread to the active list. It keeps a current pin but does not restore a pin that settling removed. A new approval also returns a settled thread. General > Organization has T3's default-off **Working section (beta)** device setting. With it enabled, unpinned active work moves into **Working** below Active and above Snoozed and Settled. Working keeps full cards and starts collapsed as **Working (n)**, with the open thread still visible. Its expansion persists independently on this device, and search reveals every matching card. Approvals, input requests, and terminal turns return cards to Active, sorted by creation, un-settle, request, completion, or observed return time. Both Active and Working use that order while the setting is on. Pinned, snoozed, and settled placement takes precedence. Working card labels show elapsed time from the turn's start without announcing each tick. The setting has its own reset and Restore defaults turns it off. Bot Code leaves out thread reordering by drag and drop, the Custom snooze time, and the Woke indicator. The filter is a searchable popup under the search field. It lists **All projects**, then **No project**, then repositories by name. Choosing a project shows only its threads and its badge replaces the folder icon. The choice persists on this device and falls back to all projects when that project is gone. While a project is chosen, **New thread** opens that project's draft. Each project row has a settings button, and right-clicking the row also opens that project's Project settings page. A fixed bottom bar contains the 32px Settings gear and T3's **Usage** button. Settings replaces the sidebar list with search and category navigation. On Settings or Usage, the bottom bar becomes Back.
- A 52px header with the repository badge, the thread title, T3's Git actions control, and fixed terminal and right-panel toggles.
- A centered 48rem conversation column. The composer floats over the bottom of the timeline. A new thread centers the composer under "What should we build in {repository}?", and that repository name is the repository picker.
- An optional right panel, 540px by default, with Terminal, Files, file, Diff, Preview, Pull requests, and pull request tabs. With no tab open, it shows T3's **Open a surface** launcher, where each row's letter opens it: **T** for Terminal, **F** for Files, **D** for Diff, **B** for Preview and **P** for Pull requests.
- An optional terminal drawer at the bottom of the conversation column. It spans the timeline and composer but not the right panel.

The terminal drawer follows T3's thread terminal drawer and renders with T3's Ghostty terminal. The header's terminal toggle, left of the right-panel toggle, and Command+J open and close it. Opening focuses the terminal, and closing returns focus to the composer. The drawer is 280px tall by default and resizes from its top edge between 180px and 75% of the window. Each thread has its own terminals, and a repository draft has its own. A thread without a project has no toggle until its first message creates its folder. A single terminal shows T3's floating toolbar with **Split Terminal Horizontally**, **Split Terminal Vertically**, **New Terminal** and **Close Terminal**. Two or more terminals show T3's tab sidebar with Single, Side by side and Stacked groups of up to four terminals. Closing a terminal asks for confirmation and stops its process. When the process exits, the terminal prints "[terminal] Process exited" and its tab closes. A terminal that cannot start, such as one in a removed worktree, prints the reason. Switching threads detaches the terminals. Their shells keep running and replay their output when the thread opens again. The open state, height, terminals and splits persist on this device. After a restart, each terminal starts a new shell. Command+K or Control+L clears the terminal. Option and Command with the arrow keys move by word and to the line ends, and Command+Backspace deletes to the line start. Selecting text offers **Copy**, and right-clicking offers **Copy** and **Paste**. On macOS, Option types the character it composes, such as $ or @ on Swedish layouts, as Ghostty does by default, and Command chords other than copy, paste and the terminal shortcuts never reach the shell. Clicking a web link opens it in the system browser. Clicking a path that matches a file in the checkout opens it in the right panel's file tab. A terminal can also open as a right-panel tab from the launcher's **Terminal** row, the **+** menu, or **T** while the launcher shows. A no-project draft shows the row disabled with T3's reason. The tab is titled with its active terminal, such as "Terminal 2", and shows T3's terminal icon. It fills the panel with the same toolbar and tab sidebar as the drawer, holds up to four terminals in one split, and Command+N in it opens another terminal tab. Terminal numbers are shared between the drawer and the panel, so a new terminal takes the lowest free number. Closing the tab asks for confirmation and stops every terminal in it, and closing or exiting its last terminal removes the tab. Each thread keeps its own terminal tabs: switching threads removes them from the panel without stopping their shells, and returning brings them back with replayed output. Only the active tab's terminals stay attached. Text uses T3's terminal font stack at the code font size, with colors from T3's terminal theme variables. Selecting terminal output offers **Add to chat** beside **Copy**. It inserts a terminal context chip with the terminal name, captured line range, and excerpt, then focuses the composer. Bot Code leaves out T3's in-app preview for links, subprocess names in tab labels, hidden drawers kept mounted for recent threads, and terminal history across app restarts.

A thread can also start without a project, as in T3 commit `6b286ae8a`. A launch with no projects opens that draft directly, a repository draft offers **or start without a project** under its heading, and Command+Option+N opens the same draft. That draft asks "What should we work on?" and moves the picker, which reads **No project**, to the line below. Each of these threads runs Codex in its own plain folder under `scratch` in the data directory, named from the date, the first words of the prompt, and a short id. They show T3's gray dashed message icon and have no workspace selector, branch picker, or Diff tab. Bot Code creates the **No project** workspace the first time it is needed, and the sidebar's project filter then lists it first. The option is absent when the data directory sits inside a Git work tree. In that case, or when creating the workspace fails, the empty window offers **Add project** instead.

Appearance follows the system by default. The local preferences owner in `src/settings/preferences.tsx` applies the system, light or dark choice, and the prompt and code font sizes. The macOS window keeps an overlay titlebar with native traffic lights at `{16, 28}`. That centers them in the 52px header, level with the sidebar toggle, as T3's Electron position `{16, 19}` does. Elements that carry T3's `drag-region` class also carry `data-tauri-drag-region="deep"`, which gives Tauri the same rule: the subtree drags and clickable children opt out.

## Browser preview

Preview occupies an ordinary right-panel tab. Its URL row, input group, navigation controls, empty state, discovery rows, and responsive toolbar port T3 v0.0.45's preview components and browser toolbar. The launcher and **+** menu expose it in repository, folder, and no-project drafts. **B** selects it while the launcher is visible. With no page, **No preview yet** offers an address and bounded discovery of local HTTP HTML servers.

The browser is a Tauri child webview positioned within the measured content host. It hides when another surface or conversation is selected, the panel closes, or an application menu or dialog is open. A new mount invalidates old layout callbacks, so a late cleanup cannot hide another conversation. The existing sidebar, chat, bottom composer, compact header and neutral colors remain the layout baseline.

The URL bar accepts HTTP and HTTPS addresses without embedded credentials. Back, Forward and Refresh reflect native navigation, including SPA history. Refresh preserves forward history. Failed or stalled loads show a bounded error and allow retry. Desktop, Tablet and Mobile choose CSS sizes; custom inputs and rotation use the same native viewport operation. Fit panel follows the available rectangle. The toolbar displays the measured CSS size. Fixed sizes scale to fit while retaining the desktop user agent. Browser state is scoped to a conversation or project draft and lasts for this app session; hidden views retain it within a finite cache.

Agent browser tools operate on their own conversation's preview. Open requests may expose that tab; navigation and background opens retain the user's panel intent. Snapshots return current element references and optional PNGs, and actions refuse stale or ambiguous targets. The same browser remains usable through its toolbar and page controls. Automation is limited to main-frame DOM events; native input parity is not guaranteed. Native PNG capture and appearance overrides currently run on macOS.

Application navigation shortcuts remain available while the preview page has focus. Command palette and other covering dialogs hide the native page until dismissed. Ordinary page typing and composer-local shortcuts stay in their own controls.

Recording, simulators, cookie import, annotation and picture-in-picture controls are omitted. Native history and the final browser verification currently target macOS WKWebView.

## Thread lifecycle

The thread menu ports T3 v0.0.45 `threadActionMenu.logic.ts` and `Sidebar.tsx`. After the arrangement actions, it shows **Rename thread**, the **Copy** submenu with **Path**, optional **Branch**, and **Thread ID**, **Archive thread**, and destructive **Delete**. Rename replaces the card or shelf title with T3's inline input. Enter or blur saves a trimmed nonempty title. Escape cancels. A failed save keeps the editor and shows the error. The input and rename switching stay disabled while a save is pending. Copy reads the thread's checkout path and branch, or the local repository path and branch. Clipboard failures appear in the sidebar.

Archive hides an idle thread from every ordinary list, search, count, and shortcut target. The open thread moves to the next card or its project's draft after the operation succeeds. Archive stores its former pin, settle, kept, or automatic placement and clears its snooze. **Settings > Archived** ports T3's grouped project rows, archive and creation ages, **Unarchive** button, and context-menu **Unarchive** and **Delete**. It respects the settings project scope and appears in settings search. Its summaries come from persisted thread metadata, so an unavailable repository does not hide its archives. Unarchive restores the saved placement. An automatically managed thread with old activity can settle again after restoration.

Delete uses T3's confirmation text, "This permanently clears conversation history for this thread." It stops all terminals owned by that thread and removes its history, submission receipts, and pull request memberships. Shared pull request records, operations, and project review decisions remain. A running or pending conversation or an operation holding the same checkout blocks deletion before it changes anything. Successful deletion of the open thread follows the same forward navigation as archive, provided that thread is still open.

Storage adds T3's default-off **Delete worktrees with deleted threads** row and description. With it enabled, deletion tries `git worktree remove` without force after checking ownership, location, branch, changes, and ignored files. Dirty, shared, locked, unsafe, or refused worktrees remain, and a neutral status gives the reason. Deletion never removes the branch, local repository, or scratch folder. It does not queue past deletions for later cleanup. If the database fails after Git removal, the visible conversation remains and the existing missing-worktree restore path can recreate its checkout on the next message.

## Command palette

Command+K opens the palette from chat, Settings, Usage, and the right panel. A focused terminal keeps Command+K for clearing its output. The palette ports T3 v0.0.45's `CommandPalette`, `CommandPaletteContent`, `CommandPaletteResults`, `commandPaletteBus`, and command, autocomplete, and keycap class strings. Its modal sits near the top of the window with T3's search input, grouped rows, highlighted selection, shortcut labels, and Navigate and Close footer. The background cannot take focus or run shortcuts while the palette is open.

An empty query shows actions and up to twelve recent threads. Search includes titles from every project's nonarchived summaries, including snoozed and settled threads. Message search reads prompts and user and assistant text only from snapshots already loaded in this session. It shows that coverage in the palette and does not fetch every thread's history. Queries ignore case, accents, and repeated whitespace. Every query word must match. Title matches rank before message matches, and recent activity breaks ties. A leading `>` searches actions only.

The action table owns labels, eligibility, execution, and shortcut descriptors. Both the palette and `src/lib/shortcuts.ts` read it. Working actions include new thread, new thread without a project, **Go to file**, **Search project contents**, open Settings, toggle sidebar, terminal drawer and right panel, pin or unpin, settle or un-settle, snooze presets or wake, rename, copy path, optional branch and thread ID, archive, delete, and archived-thread restoration. Pin and settle use the same in-place operation as their shortcuts. Snooze, archive and deletion keep the existing successful forward navigation. Deletion keeps its native confirmation. Archived threads have their own restoration submenu and remain absent from ordinary search. Core refusals still report concurrent checkout operations that summary metadata cannot prove available.

Arrow keys navigate and Enter runs the highlighted result. Escape closes the palette before an underlying Settings search or page consumes it. Backspace on an empty submenu query returns to its parent. Ordinary dismissal restores the control that opened the palette, with the composer as a fallback; actions such as rename, open Settings and toggle terminal focus their own control. Opening requests cancellation of an existing in-app dialog through its normal handler. If an active operation refuses cancellation, the palette opens with a wait message and no executable results until dismissed. Rename reveals its existing inline editor even when the sidebar is collapsed or filtered. Bot Code omits T3's theme editor, cloning, and environment actions.

Command+P opens T3's **Go to file** picker, and Command+Shift+F opens **Search project contents**. Both actions use T3's labels and bindings in the shared action table and remain available in the palette for an assigned checkout. A focused terminal keeps these chords. The dialogs port v0.0.45's `files/ProjectFilePicker.tsx`, `ProjectFilePicker.logic.ts`, and `search/ProjectContentSearchDialog.tsx`. They use the existing command dialog, input, result rows, neutral colors, and Navigate, Open file, and Back footer. The content dialog groups matching lines beneath each file and keeps T3's **Match case**, **Match whole word**, and **Use regular expression** controls. Arrow keys select a row, Enter opens it, and Escape dismisses the dialog. Changing the query or options prevents opening older results while the new search waits.

A Rust checkout index adapts T3's `WorkspaceSearchIndex.ts` with the `ignore` crate and ripgrep's matching libraries. Files, the picker, `@` mentions, and content-search candidates share its paths. It respects `.gitignore`, nested rules, `.ignore`, and Git's global excludes, including files that Git tracks but ignore rules now exclude. The former 40,000-file refusal is removed. The picker returns at most 200 rows and mentions at most 50. Content results and scan work are bounded, and the dialog reports incomplete coverage and skipped files. Content search skips binary files, invalid UTF-8, and files above the viewer's 1 MB text limit. Results open the existing right-panel Files view. Content results select and reveal their one-based source line, including when that file tab is already open.

Both dialogs provide **Refresh** to rebuild the shared index after external changes. Their layout and line navigation were verified in the native app with an isolated data directory, a disposable 50,002-file repository, and a 1000×620 window. [Project search verification](project-search-verification.md) records the checks, timings, and limits.

## Only working controls appear

**New thread** opens T3's searchable **New thread in…** palette when all projects are shown and several repositories are open. The current repository comes first. Rows show its badge, name, **Local**, and path, followed by **No project** when available. Effective `thread.jump.1` through `thread.jump.9` keybindings select the visible numbered rows. A selected sidebar project, a single repository, and Shift-click open the draft directly. Command+Shift+N opens a draft in the current project.

**Add project** opens the palette's **Sources** page. **Local folder** opens T3's directory browser at `~/`. Directory rows and Enter navigate, while **Add** and Command+Enter submit the exact typed path. Absolute and home-relative paths work. `./` and `../` resolve against the selected repository and require one. Prefix search hides dot directories until the prefix starts with a dot. The input's back arrow and empty-input Backspace return to the previous page. **Open in Finder** offers the native directory chooser. Cancel keeps the browser open. Pending operations disable repeated submission, and failed reads or repository opens retain the path and show an error. Bot Code adds existing Git repositories only, including a directory inside a repository. It leaves out T3's new-project, clone, and remote-source controls.

Every repository turn captures the checkout before Codex starts and after it finishes. T3's changed-files card appears below the turn with its file tree, line counts, folder expansion, and **Open diff**. Clicking a file opens that turn's diff and reveals the file. The Diff scope menu keeps Working tree, Unstaged, and Staged, and adds T3's **Latest turn** and **Turn** submenu. Choosing Turn 2 compares only that turn's two checkpoints, regardless of later changes. Missing checkpoints show their reason instead of a diff against HEAD. Threads without a project have no checkpoint diff.

Hovering a user message reveals T3's **Edit from here** button beside Copy. It is disabled while the conversation or its checkpoint capture runs. The dialog copies T3's layout and offers **Cancel**, **Revert files too**, and **Revert and keep changes**. Both rewind the timeline to before that message and return its prompt and attachments to the composer, preserving current unsent input. Pending file staging or the 100-file limit defers the whole recovery and explains how to make room. Original recovered attachments survive restart until an accepted send. Bot Code continues on a new native Codex thread containing only the earlier conversation, and the dialog says so. Revert and keep changes keeps the current checkout contents. Revert files too restores tracked and non-ignored files, removes later non-ignored files, preserves ignored files, and leaves restored changes unstaged when HEAD exists. Its confirmation says that the current checkout changes will be replaced. The file choice is absent when no before checkpoint exists, the thread has no project, or its worktree has been removed.

The core refuses either choice while a turn, Git action, branch switch, checkpoint capture, or cleanup holds the checkout. Preflight refusal releases the checkout without changing its files or conversation. A failure after preparation keeps a **Retry revert** control above the composer. Retry continues the saved operation and offers only its original mode. The operation and prompt survive restart. Ignored file collisions and unsafe nested repositories, submodules, or ignore-rule changes show a refusal. A successful revert does not send the returned prompt.

The composer accepts T3's mixed file attachments through **Attach files**, clipboard files, and drops. Every message has a 100-file limit. Non-image files must be nonempty and can be up to 50 MiB each. PNG, JPEG, GIF, and WebP images keep their original bytes below 10 MiB and use T3's compression pipeline above that limit. HEIC and HEIF convert to JPEG through T3's CSP-safe decoder before staging. Sources above 50 MiB and HEIC images above 64 million pixels are refused before decoding. Images can total up to 80 MiB per message. Images appear as T3's 64px removable thumbnails and its two-column timeline grid. Other files create inline file chips at the captured selection, with T3's filename-and-size rows for files without a chip. Send waits for pending staging. Image-only and file-only messages work. An image-only first message titles the thread "Image: {name}", and a file-only one uses "File: {name}". Both keep the temporary worktree branch because the name generator reads no attachments. File attachments reach Codex through the exact absolute-path notes in T3's `ProviderService.ts`. Pasted text uses its separate inspect-as-needed note. Only images reach `CodexAdapter.ts` as `localImage` inputs.

A paste of at least 32 KiB of UTF-8 text replaces the selection with a file chip. Names start at `pasted-text.txt` and avoid existing names without letter case. Command+Shift+V, or Control+Shift+V elsewhere, inserts editable clipboard text at the selection. The native app reads text directly because WKWebView does not emit a paste event for that chord. Browser previews retain T3's one-paste bypass within a second, cleared by blur. Structured chip clipboard data preserves its records. Image clipboard data takes precedence over accompanying text. Ordinary generic files take precedence only when clipboard text is absent. A large paste that cannot attach stays inline when the prompt still fits its 100,000-byte limit. Otherwise T3's large-paste error title and detail explain how to make room.

ArrowUp recalls the active thread's earlier user prompts only when the composer has no typed text, chips, or attachments. ArrowDown advances and clears after the newest entry. Recalled prompts carry text only and strip sent context references. History navigation uses T3's first and last visual-line checks, including wrapped paragraphs. Suggestion menus, approvals, questions, modifiers, and IME input keep their own keys. Editing or switching composer scope ends recall.

Command+S, or Control+S elsewhere, stashes a complete draft after native persistence succeeds. The app-global stash keeps the newest 20 entries and retains every chip record and native attachment reference across restart. With an empty composer, the shortcut restores its sole entry directly or toggles T3's stash picker. The shoulder badge, pulse, menu rows, arrow navigation, Enter, Escape, and modified Backspace follow `ComposerStashBadge.tsx` and `ComposerStashMenu.tsx`. Restoring appends text with a blank line, remaps chip IDs, and keeps destination model settings. Capacity refusal restores nothing. Destination draft persistence precedes deletion of the stash copy. A failed save keeps its source, and a changed composer activation or revision prevents clearing another draft.

Drops on regular, slim, and filtered sidebar rows queue files for that exact conversation before navigation. The destination consumes them once after its draft activates, using the same composer ingestion path. Failed navigation removes only its own drop. Bot Code leaves out T3's expanded image preview, video previews, and the whole-column drop target. Drops elsewhere do nothing. The composer has model, reasoning effort, and access-mode menus backed by per-thread Codex settings and the live model catalog. Left of Send or Stop, T3's context window meter appears once Codex reports the thread's token usage. Its ring fills with the share of the context window in use and turns red above 90%. Hovering or focusing it shows a card with the percentage, the used and maximum tokens, the total processed, and T3's note that context compacts automatically. The card does not take focus. General > Application has T3's **Context window indicator** switch, which is on by default. Restore defaults turns it back on. The context strip under the composer starts with T3's workspace selector on a new thread: **Current checkout** or **New worktree**. Once a thread exists, the left side shows a fixed **Local checkout** or **Worktree** label. The right side is T3's branch picker in every state. A worktree draft uses it to choose the base, which defaults to the repository's default branch, and its **Start from origin** switch. The trigger then reads "From origin/{base}" or "From {base}". Elsewhere, picking a ref switches the checkout's branch, and a typed name that matches no ref offers **Create new ref**. Branches checked out in another worktree are disabled. Bot Code leaves out T3's pull request badge, pull request checkout, and a general worktree reuse picker. Plan implementation can reuse its source checkout. Sidebar rows of worktree threads show T3's worktree icon and the worktree branch. A new worktree starts with a temporary `botcode/<random>` branch and a matching random folder. Its first accepted message generates a short branch name in the background using the selected Codex model. Bot Code applies the name after that turn releases the checkout. The folder stays in place, and the sidebar and branch picker refresh together. Naming keeps the branch the worktree started from as the pull request base. Local checkouts, manually named branches, and later messages do not start naming. A switch, Git action, later message, cleanup, project removal, or provider loss cancels pending naming. Generation errors and existing upstream or remote tracking refs leave the temporary branch in place. A name collision adds the original random suffix without overwriting another branch.

Codex's `turn/plan/updated` notifications populate a separate typed execution checklist on the current turn. The composer ports T3's **Tasks** shoulder tab and drawer, with the current step, completion count, two to ten progress segments, status icons, and observed durations for completed steps. Expanding the tab shows every task. Only a running step says **now**. Approvals and input requests hide the task controls. Empty lists, all-completed lists, terminal turns, and thread changes close the drawer. A new turn starts without a checklist. Interrupted, failed, or lost turns retain the last observed statuses in persisted history, while their task controls disappear. Restart preserves task history and marks unfinished live execution as lost. Execution tasks do not affect Plan mode, proposed plan cards, or implementation follow-ups.

Follow-up input ports T3 v0.0.45's `queuedMessageStore`, `QueuedMessageSender`, `ComposerPrimaryActions`, and dashed `MessagesTimeline` rows. Send stays beside Stop when text or attachments are ready, including during approvals. General > Application has T3's **Follow-up behavior** menu with **Queue** and **Steer**, default Queue. Enter uses that choice while a turn runs. Queue captures the prompt, staged attachments, and context chips, and current send settings. The first row's **Send now** steers the exact running turn, or starts a turn when idle. Later rows cannot overtake it. Connecting input waits in the queue. Approvals block delivery while the composer stays editable.

Queued rows appear under the timeline with T3's dashed border and icon actions. Automatic sends wait for successful completion, saved final checkpoints, resolved approvals, and confirmed delivery. Failed, interrupted, or lost turns hold the queue for explicit Send now. Stop holds it before interruption and restores every unsent row in order beside existing draft input. Remove restores one row. Staging or the file limit leaves recovery held and visible. In-flight rows cannot be recalled. An uncertain IPC response shows **Check delivery** for the same operation. Queues survive thread switches and send from the application root, including hidden threads. They live in memory and disappear on renderer reload or app exit. Accepted input persists in conversation history.

Steering appears as an ordinary user bubble inside the existing turn, visible outside completed work folds. It offers Copy only. A failed or uncertain steer keeps its delivery explanation in that bubble. The original prompt's Edit from here removes the entire turn including its steers, and restores only the original prompt and attachments. Opening rewind holds and restores unsent queued input. Archive, delete, and project removal require removing queued rows first.

Sending exactly `/usage-limits`, in any letter case, opens T3's **Usage limits** notice above the composer and sends nothing to Codex. It works on a draft and while a turn runs. The notice shows the Codex plan, then each limit window with its remaining share, the even-spending mark, pace and time to reset, as of the moment it opened. Dismissing it, a new turn, a new approval or another thread closes it. The **Usage** button opens T3's Usage page with only its limits section, showing the same windows for the Codex account. **Refresh** reads the limits again. Codex also pushes changes while turns run. Back or Escape returns to the conversation. Bot Code leaves out T3's **Compact context** button, reset credits, token and cost history, and multiple accounts.

A thread in a repository checkout shows T3's Git actions control at the right of the header. Drafts, threads without a project, and removed worktrees show none. Its quick-action button runs the step T3 picks for the branch, such as **Commit, push & PR**, **Commit & push**, **Push & create PR**, **Create PR**, **Pull**, or **View PR**, and shows only its icon when the header is narrow. The chevron menu lists **Commit**, **Push**, and **Create PR** or **View PR**. A disabled button or item explains itself on hover. An action that commits opens T3's commit dialog first. It shows the branch and the changed files with their line counts, shows an editable generated commit message with an optional message field, and offers **Cancel** and a button named for the whole action, such as **Commit** or **Commit, push & PR**. Command+Enter starts it. The message field uses T3's "Commit message (optional)" label and "Leave empty to auto-generate" placeholder. ## Editable files

The Files tab edits text files in place, as T3 v0.0.45's `FilePreviewPanel.tsx` does. `src/panel/fileSaveCoordinator.ts` and `src/panel/useFileSaveCoordinator.ts` port T3's save coordinator and its hook. ## Domain data the interface needs

T3's timeline reads timestamps that Bot Code did not record before this baseline. Each `Turn` now stores `started_at` and `completed_at` in Unix milliseconds. `ThreadSnapshot::stamp_completions` records completion on every save. Turns saved earlier have neither value and show "Worked" instead of "Worked for 8.6s". `ThreadSummary` carries `updated_at` for the sidebar's relative time, `awaiting_approval` for its **Approval** status, and `pinned_at_ms`, `snoozed_until_ms`, and `settled_at_ms` for the sidebar sections. It derives `archived_at_ms` and `created_at_ms` for Archived settings. Each thread stores a `placement` of `auto`, `kept`, `pinned`, `settled`, or `archived`, and an optional `snooze` with its wake time and the time it was set. An `archived` placement carries its timestamp and a `LivePlacement` restore value that excludes archive, so archives cannot nest. A `pinned` placement carries `kept`, T3's active override, when pinning un-settled the thread. Pins saved without `kept` load with it false. Snapshots saved with the earlier `settlement` field load it as `placement`. The core reports the wake time only while no approval or newer turn result cancels the snooze. The client compares that time with its own clock. The effective settled time is derived when it is read. The core reads `sidebarAutoSettleAfterDays` and each `projectOverrides` entry from `settings.json` when it opens and after every settings save. A missing or invalid value means 3 days, and `null` turns auto-settling off. A save that changes a thread's classification sends a change hint for that thread. Before a pin, settle, snooze, prompt or approval changes a thread, the core stores a due auto-settle as `settled` at the last activity, without the pin or the snooze, as T3's auto-settle command does. `pinned_at_ms` is empty while a pinned thread reads as settled. File-change items carry their `paths`, so a single change shows its file name. Each Codex item kind has its own turn item, such as `reasoning`, `mcp_tool_call`, `web_search`, and `context_compaction`, with the fields its row needs. Snapshots saved with the earlier `other` items load them as reasoning or context compaction and drop the rest, which carried no text. Each thread stores its latest `context` usage from Codex: the tokens in the context window, the window's size and the total processed. Threads saved earlier have none and show no meter.

## How parity is checked

## PR reviews

Open a saved pull request from the Pull requests list to review it in its own right panel tab, titled with its number, such as **#24**. Summary, Timeline and Code use the saved GitHub identity. They remain available after a branch switch or worktree removal. Files and Diff still use the local checkout.

The detail follows T3's pull request view at commit `3e6b450`. The top row shows `owner/repo`, which opens the repository, and the number, which opens the pull request and takes the state color. On the right are the primary lifecycle control and T3's **…** menu. Below them are the title, the author's avatar and login with the relative update time, a copyable `gh pr checkout` command, the base and head branches, and GitHub's own totals of changed files, additions and deletions. Summary, Timeline and Code are a segmented control. On Summary, the checks rollup sits at the right of that row and opens a popover that lists each check with a Details link. Avatars load from `avatars.githubusercontent.com`, which the content security policy allows, and fall back to the login's initial.

Summary lists the reviewers, ringed by their latest outcome, and the labels in their GitHub colors. Both are read-only and read None when empty. A collapsible Description renders the body. When GitHub reports that the signed-in account may update the pull request, hovering the title or the description shows T3's pencil. GitHub allows this on open, closed and merged pull requests. The title edits in place, where Enter saves and Escape cancels. The description opens T3's Write and Preview editor, where Cmd or Ctrl+Enter saves, Escape cancels, and an empty description is allowed. An edit applies after the head moves, but not after the account changes. A saved edit refreshes the detail. A refused or failed save keeps the editor open with its text and shows the reason below it. A collapsible Checks section, closed by default, lists every check and offers Fix check on failed or cancelled ones. The **…** menu holds **All pull requests**, which returns to the list, Refresh, Explain with Codex, Fix findings, every permitted lifecycle action that the header does not already show, and Open on GitHub. Timeline combines opened, commits, comments, reviews, and merged or closed events in newest-first order. Dates that GitHub omits or returns invalid remain unavailable. It keeps original reviewed commits and diff hunks, GitHub resolved/outdated state, review outcomes and source links. Local Fix, Dismiss with a reason, Needs decision and Clear decision preserve their original observation and save through the native owner. Replies and resolve/unresolve appear only when GitHub permits them for the signed-in viewer and exact conversation.

Code renders the remote pull request files with the pierre diff, as T3's Code tab does. Its toolbar shows the file count on the left. On the right are the whitespace, collapse all, stacked or split, line wrap and file tree controls, which share the Diff tab's saved choices. Each file is a collapsible row with its status icon, path and `+a −d`. Files start collapsed, and clicking a row or its chevron toggles it. An expanded file shows line numbers, syntax colors, added and deleted lines, and "N unmodified lines" between hunks. While the signed-in account may review, hovering a line number shows T3's **+** button. It adds a line comment to the review draft and opens it under that line with the cursor in it. Only lines that GitHub returned in the diff accept a comment. A context row in the old column of the split view comments on the same row's new line. Drafted comments stay under their lines and also appear in the review composer, and the trash button discards one. Missing, binary, oversized and truncated patches are listed after the diff with their reason and a GitHub link. Bot Code leaves out T3's commit picker, the per-file Viewed checkboxes, multi-line comments, existing conversations under their lines and expanding unchanged context. Failed and limited sections have explicit typed warnings. Successful sections remain visible when another section fails. A failed core read retains the shared last-known status as stale.

The review composer sits at the panel bottom and opens from Review. Session drafts belong to a pull request, account and head. Summary and line comments survive tab and conversation navigation. Comment, Approve and Request changes submit only when explicitly selected and sent. Authors can Comment on their own pull request. A changed head or account requires refresh and an explicit discard of older anchors. Failed or uncertain submissions retain drafts. A confirmed review ID clears only captured revisions that were not edited while submission ran. An uncertain outcome requires checking GitHub and explicit acknowledgment before a new submission.

Ask Codex, Explain with Codex, Fix finding and Fix check append context and any coverage warnings to the conversation draft and focus its composer. Existing text stays intact. The user sends it through the existing Send control. Preparing this text never switches the checkout.

## Linked pull requests

Native Git creation and reuse save the resulting GitHub PR on the originating conversation. The sidebar badge opens the conversation's pull request in the existing right panel. The Git control, its result toast and the panel launcher open it too. With exactly one linked PR they open its detail directly. Otherwise they open the **Pull requests** list. The launcher and the **+** menu offer **Pull requests** only while the conversation links at least one PR. Several conversations can share one PR, and one conversation can retain several PRs. Each list row shows the saved lifecycle, branch names, a working GitHub source link, and **Unlink**. The URL field links an exact GitHub.com PR. Unlinking prevents automatic discovery from restoring that association.

Agent tools use the same saved links and invalidation hints. `link_pull_request`, `unlink_pull_request`, and `list_thread_pull_requests` infer their conversation from the tool session. Link and unlink accept a GitHub.com URL or a repository and number. Repeating a link preserves its original source and linked time. The tools do not create or change pull requests on GitHub.

Saved links remain available after a branch switch, restart, or worktree removal. After restart, saved status appears as last known until GitHub confirms it. A failed refresh retains that status and shows the failure. Native reads are shared across conversations and continue with the panel closed. Open PRs on active conversations refresh about once a minute. Closed PRs and PRs linked only to settled conversations refresh about every fifteen minutes. Confirmed merged PRs stop routine polling. Failed reads back off to fifteen minutes. **Refresh** requests a new read and checks the checkout for an unambiguous PR.

Discovery checks the base repository and actual head repository and branch, including a configured upstream base with an origin fork. Native creation and reuse target the origin repository. A PR created against a different base repository can be linked by URL. The former branch-bound Reviews entry has been replaced by linked review detail.

## PR lifecycle

Saved PR detail exposes working lifecycle controls from GitHub permissions and repository policy. The primary action follows the observed state. It offers Resolve conflicts, Ready for review, an allowed merge method, required merge queue or auto-merge in the header, using T3's labels such as **Squash and merge** and **Auto-merge (squash and merge)**. Armed auto-merge shows T3's blue badge with its method, and a queued, merged or closed pull request shows a badge in the same place. The **…** menu includes supported draft, ready, close, reopen, branch update and auto-merge controls. Conflicts keep permitted auto-merge available as a secondary action. GitHub's required queue chooses its merge method.

Every lifecycle mutation opens a confirmation with the captured PR identity, head and account. Auto-merge warns that GitHub may merge immediately. A changed head or account refuses the captured request. Checkout-changing actions also refuse while a linked conversation uses that checkout. Disable auto-merge remains available during agent work.

Accepted queue, armed auto-merge and unavailable confirmation reads stay pending. The conversation stays active until a fresh host observation confirms the outcome. Reconcile reads GitHub without replaying the original mutation. Pending receipts and links survive restart.

An interrupted branch update keeps its outcome unknown. When the same PR is open at another head, Continue from inspected head shows the original method, head and account beside the current head and account. Its explicit confirmation warns that GitHub may still apply the earlier update and continuation does not cancel it. Successful continuation saves the inspected identity while preserving the original request. A fresh same-node merged observation also clears obsolete lifecycle blockers without claiming the earlier uncertain operation succeeded.

Resolve conflicts and Fix findings append captured identity, current unresolved findings, failed checks and coverage warnings to the conversation draft. They include startup failures. They preserve existing text and require the user to Send.

General settings adds Auto-settle merged pull requests independently from Auto-settle inactive threads. Its project override, inheritance indicator and reset follow the existing settings structure. Eligible conversations settle after all linked PRs merge and a merge is recent enough for their trusted activity. New work, kept placement, snooze, approvals and running work protect active conversations. The settled age remains the conversation's activity age.

## Error recovery and keybindings

Error recovery ports `routes/__root.tsx`, `components/ui/standalone-page.tsx` and `components/RenderErrorBoundary.tsx` from T3 v0.0.45. The router root and startup use T3's full-page error UI. Code highlighting and Markdown rendering use plain-text fallbacks at T3's render boundaries. Bot Code additionally isolates right-panel content and the terminal drawer. Their errors use the same T3 UI within the existing panel dimensions. The panel tabs, conversation sidebar and composer stay usable. **Try again** remounts the failed subtree, and navigating to another tab or checkout resets the relevant boundary. Copy failures show an error instead of claiming success.

The Keybindings page ports `components/settings/KeybindingsSettings.tsx` and its logic. It keeps T3's row and header classes, key pills, source badges, search, conflict warnings and rule edits. Conditions use a compact text field with variable hints. The row menu resets one exact custom rule to its default or removes it, preserving alternate rules for the same command. Reset and removal appear only when they apply. Unsupported T3 commands remain in copied files but are absent from the command picker and runtime conflict resolution.

The file at `BOT_CODE_DATA_DIR/keybindings.json` is an ordered JSON array of `{ key, command, when? }` rules. The normal data directory applies when the environment variable is unset. It accepts T3's comments, trailing commas, key grammar and condition grammar. Known T3 command IDs remain unchanged; Bot Code adds IDs for its settings page, page close, terminal clear and other existing local actions. The settings page displays the resolved file path. Bot Code does not inspect T3's data directory.

One TypeScript parser validates file entries before input handlers see them. Invalid entries produce indexed diagnostics and leave their command's default active unless another valid rule overrides it. A malformed whole document keeps all defaults and blocks settings writes. Rust owns fixed-path file reads and conditional atomic writes. A settings edit rereads the current file, preserves unrelated raw entries, and retries if another writer changed it. Confirmed saves update the shared action, terminal, composer and project-script resolver and their labels. The last matching rule wins. File edits reload on focus and every two seconds. Legacy device script shortcuts migrate into the file before their old UI-state entry is removed.
