# UI baseline

Z1 renders the T3 Code interface for every workflow it implements. The reference is T3 Code v0.0.45 (`pingdotgg/t3code` tag `v0.0.45`, commit `6c8fed35d`), the build in the installed desktop app. T3 Code is MIT licensed. Ported files name their source in a one-line header.

## Styles come from T3, not from a lookalike

`src/t3-theme.css` is T3's `apps/web/src/index.css`, copied verbatim. Regenerate it with `scripts/port-t3-theme.sh <t3code-checkout>`. Tailwind v4 compiles it through `@tailwindcss/vite`, so components use T3's own utility classes and tokens: `bg-sidebar`, `text-secondary-label`, `--chat-max-width`, `alert-glass`. `src/styles.css` imports the theme and holds the only Z1 overrides: root typography, which T3 sets from JavaScript, and the macOS traffic-light inset.

`src/ui/controls.tsx` copies T3's `buttonVariants` and `toggleVariants` tables and the select trigger and item classes. Components copy T3's class strings literally. A hand-written approximation drifts the first time T3 changes a token. A copied class string can only drift when the copy is stale.

## Layout

The shell matches T3's desktop app:

- A 256px left sidebar, resizable from 208px and collapsible with Command+B. It holds the brand row, thread search, T3's project filter, **Add project**, **New thread**, and T3's Pinned section, Active list, Snoozed shelf and Settled shelf across every repository. Pinned threads show as cards at the top, newest pin first. They have no header, because T3 labels them only while dragging. The pin icon on a pinned card unpins it. Active threads show as cards below them, newest activity first. Hovering a card shows a clock button and **Settle** in place of its time, except while an approval waits. The clock opens T3's snooze presets: In 1 hour, In 3 hours, This evening while 6 PM is more than an hour away, Tomorrow at 9 AM, and Next week on Monday at 9 AM. Right-clicking any thread opens T3's thread menu with Pin or Unpin, Settle or Un-settle, and a Snooze submenu with the same presets, or Wake when the thread is snoozed. The **Snoozed** shelf appears above Settled while any thread is snoozed. Its slim rows show the soonest wake first, the time left, such as "2h", and a **Wake thread now** button on hover. It starts collapsed as "Snoozed (n)" and shows only the open thread's row until expanded. A snoozed thread comes back when its wake time passes, without a reload. It comes back early when an approval arrives, or when a turn completes or fails after the snooze. A pinned thread keeps its pin while snoozed and comes back into Pinned. The **Settled** shelf sits at the bottom of the list as slim rows, most recently settled first, with a dimmed badge, the title, the settled age, and an **Un-settle** button on hover. It starts collapsed as "Settled (n)" and shows only the open thread's row until expanded. Expanded, it shows 10 rows and then **Show more** in steps of 25. Both shelves remember their state on this device. Search shows every matching snoozed and settled row. Settling or snoozing the open thread opens the next card, or a new draft in its project when none is left. Command+Shift+S settles or un-settles the open thread in place, and Command+Shift+P pins or unpins it in place. Pinning clears a settle or a snooze. Settling clears a pin or a snooze. Snoozing keeps the pin or settle. A thread settles by itself after its project's auto-settle limit without activity, 3 days by default, unless the user un-settled it or it is snoozed. An idle pinned thread settles by itself too and loses its pin, as in T3. Pinning a settled thread un-settles it, so it stays pinned until its next activity and does not settle by itself before then. A new prompt clears the snooze and returns a settled thread to the active list. It keeps a current pin but does not restore a pin that settling removed. A new approval also returns a settled thread. Z1 leaves out T3's Working shelf, drag and drop, the Custom snooze time, and the Woke indicator. The filter is a searchable popup under the search field. It lists **All projects**, then **No project**, then repositories by name. Choosing a project shows only its threads and its badge replaces the folder icon. The choice persists on this device and falls back to all projects when that project is gone. While a project is chosen, **New thread** opens that project's draft. Each project row has a settings button, and right-clicking the row also opens that project's Project settings page. A fixed bottom bar contains the 32px Settings gear. Settings replaces the sidebar list with search and category navigation, and the bottom bar becomes Back.
- A 52px header with the repository badge, the thread title, T3's Git actions control, and a fixed right-panel toggle.
- A centered 48rem conversation column. The composer floats over the bottom of the timeline. A new thread centers the composer under "What should we build in {repository}?", and that repository name is the repository picker.
- An optional right panel, 540px by default, with Files, file, Diff, and Reviews tabs.

A thread can also start without a project, as in T3 commit `6b286ae8a`. A launch with no projects opens that draft directly, a repository draft offers **or start without a project** under its heading, and Command+Option+N opens the same draft. That draft asks "What should we work on?" and moves the picker, which reads **No project**, to the line below. Each of these threads runs Codex in its own plain folder under `scratch` in the data directory, named from the date, the first words of the prompt, and a short id. They show T3's gray dashed message icon and have no workspace selector, branch picker, or Diff tab. Z1 creates the **No project** workspace the first time it is needed, and the sidebar's project filter then lists it first. The option is absent when the data directory sits inside a Git work tree. In that case, or when creating the workspace fails, the empty window offers **Add project** instead.

Appearance follows the system by default. The local preferences owner in `src/settings/preferences.tsx` applies the system, light or dark choice, and the prompt and code font sizes. The macOS window keeps an overlay titlebar with native traffic lights at `{16, 28}`. That centers them in the 52px header, level with the sidebar toggle, as T3's Electron position `{16, 19}` does. Elements that carry T3's `drag-region` class also carry `data-tauri-drag-region="deep"`, which gives Tauri the same rule: the subtree drags and clickable children opt out.

## Only working controls appear

T3 shows controls that Z1 cannot back yet: attachments, the terminal drawer, and usage. Z1 leaves them out. The composer has model, reasoning effort, and access-mode menus backed by per-thread Codex settings and the live model catalog. The context strip under the composer starts with T3's workspace selector on a new thread: **Current checkout** or **New worktree**. Once a thread exists, the left side shows a fixed **Local checkout** or **Worktree** label. The right side is T3's branch picker in every state. A worktree draft uses it to choose the base, which defaults to the repository's default branch, and its **Start from origin** switch. The trigger then reads "From origin/{base}" or "From {base}". Elsewhere, picking a ref switches the checkout's branch, and a typed name that matches no ref offers **Create new ref**. Branches checked out in another worktree are disabled. Z1 leaves out T3's pull request badge, pull request checkout, and reuse of another worktree. Sidebar rows of worktree threads show T3's worktree icon and the worktree branch.

A thread in a repository checkout shows T3's Git actions control at the right of the header. Drafts, threads without a project, and removed worktrees show none. Its quick-action button runs the step T3 picks for the branch, such as **Commit, push & PR**, **Commit & push**, **Push & create PR**, **Create PR**, **Pull**, or **View PR**, and shows only its icon when the header is narrow. The chevron menu lists **Commit**, **Push**, and **Create PR** or **View PR**. A disabled button or item explains itself on hover. An action that commits opens T3's commit dialog first. It shows the branch and the changed files with their line counts, asks for a required commit message, and offers **Cancel** and a button named for the whole action, such as **Commit** or **Commit, push & PR**. Command+Enter starts it. On the default branch, a push or a pull request first asks for confirmation with **Abort** and **Continue**. While the action runs, a toast below the header names the current step. The finished toast shows the result and offers **View PR**, **Push**, or **Create PR** when one applies. When a step fails after an earlier step landed, the toast keeps what landed, such as "Committed abc1234", and names the step that failed. A Codex turn in the same checkout disables the control, and Z1 refuses a prompt or a branch switch there while a Git action runs. Pull requests need the GitHub CLI signed in. Without it, commit and push still work, and the pull request items say what is missing. Z1 leaves out T3's generated commit messages and pull request text, file selection in the commit dialog, **Commit on new branch**, the feature-branch choice in the default-branch confirmation, **Publish repository**, providers other than GitHub, the pull request badge in the sidebar, hook output, and background remote polling.

The model picker has T3's Favorites and provider rail, with Codex as the current configured provider. Stars save provider and model pairs in device preferences. Favorites survive appearance and font resets. Search hides the rail and searches the live catalog. Model and star buttons are separate grid controls, so starring does not select a model or close the picker.

## Settings

Settings uses T3's compact breadcrumb header, centered page and grouped rows. General and Project open with T3's scope sentence, "Applying settings for", followed by a project picker. The picker lists **All projects**, then **No project** and repositories by name. The URL's `project` parameter holds the choice. Category links keep it, while Command+, and the Settings button open settings for all projects, and leaving settings drops it. Appearance, Keyboard shortcuts and Storage apply to the device and have no sentence. General describes Codex and the conversation access controls, sets where new threads start, whether new worktrees start from origin and when idle threads settle, and restores device preferences. With **All projects** picked, those two rows edit the device defaults. With a repository picked, they read and write that project's override, which the composer uses for that project's new threads. Each row shows T3's layers button, which lists the project and all-projects values and checks the one that applies. T3's reset button appears beside a project override, or beside a device default that differs from the built-in value. **No project** disables both rows, because those threads start in their own folder. The Organization group holds T3's **Auto-settle inactive threads** switch. While it is on, **Days of inactivity before auto-settle** takes a whole number from 1 to 90, and any other entry snaps back when the field loses focus. Both rows share the layers button, which shows a limit such as "1 day" or "Never". This row follows the same project rules, with one difference: it stays enabled for **No project**, because those threads settle too. A project can turn auto-settling off while it stays on elsewhere. Changing the limit moves threads between the active list and the Settled shelf without a restart. Restore defaults appears only for all projects and also clears project overrides. Appearance changes system, light or dark mode and the composer font size from 12 to 20px. The code font size from 11 to 20px applies to code blocks, tool output, file previews and diffs. Picking a project adds T3's **Project** item at the top of the navigation. Its page opens with T3's note that the other pages follow the picked project, then the repository's **Name**, the project's **Workspace** override under New threads, and **Remove project** under Danger. As in T3, the auto-settle limit is not on this page. The name saves on Enter or when the field loses focus, and Escape reverts it. **No project** has no name row. Opened without a project, the page asks for one with a button per project. A project that no longer exists reads "Unavailable project" in the sentence, and both pages say it is no longer available in place of its settings. Removal asks for confirmation, then deletes the project entry and all its threads from Z1, as T3's forced project delete does, and returns to the conversation. It leaves the repository, Z1 worktrees and scratch folders on disk and drops the project's overrides. Z1 refuses to remove a project while one of its conversations is running. Z1 recreates **No project** the next time a thread starts without a project. Keyboard shortcuts documents the working sidebar toggle, the shortcut for a thread without a project, the settings shortcut, Escape, and the settle and pin shortcuts. Search matches category, section and row labels and focuses the selected setting. It offers only the rows the page shows for the picked project.

Storage follows T3's Storage page and shows its **Worktrees** section with two rows. **Delete inactive worktrees** uses T3's retention control: a days stepper from 1 to 3650 beside a switch. Switching it on sets 8 days, and off shows a muted "Off" in place of the stepper. Typed days apply on Enter or when the field loses focus. **Delete unchanged worktrees** is a switch that removes worktrees with no commits beyond the default branch. Both rules start off and save as `storageCleanup` in `settings.json`, which the Rust runtime reads before every sweep. A missing or invalid value counts as off. The sweep runs once after startup, then hourly, and right after settings are saved. It only removes a Z1 worktree that belongs to exactly one idle thread, is clean with no untracked files, is on the thread's branch, and holds no ignored files other than `node_modules` folders. The inactive rule uses the thread's latest turn start or completion time. The unchanged rule fetches the default branch from origin when the repository has one. Removal runs `git worktree remove` without force and keeps the branch, the thread and its stored path. A removed thread still opens. Its right panel and the line above the composer read "This thread's worktree was removed to save space. Send a message to restore it." The next message recreates the worktree at the same path from the kept branch before Codex starts. If that fails, Z1 refuses the message and shows why. Z1 leaves out T3's **Delete worktrees with deleted threads**, because Z1 cannot delete threads, and **Delete merged worktrees**, because Z1 does not track whether a pull request merged. It also leaves out the **Artifacts and logs** section, because Z1 saves no browser artifacts or rotated logs, and the per-project **Automatic worktree cleanup** override.

Command/Control+, opens settings. Back or Escape returns to the conversation with its draft, thread search, selected thread, panel tabs and scroll retained. An active settings search consumes Escape first. Collapsed sidebars have a Back button in the settings header. Device preferences persist in local storage after schema validation. Storage failures appear in settings while changes continue to apply in memory.

## Domain data the interface needs

T3's timeline reads timestamps that Z1 did not record before this baseline. Each `Turn` now stores `started_at` and `completed_at` in Unix milliseconds. `ThreadSnapshot::stamp_completions` records completion on every save. Turns saved earlier have neither value and show "Worked" instead of "Worked for 8.6s". `ThreadSummary` carries `updated_at` for the sidebar's relative time, `awaiting_approval` for its **Approval** status, and `pinned_at_ms`, `snoozed_until_ms` and `settled_at_ms` for the sidebar sections. Each thread stores a `placement` of `auto`, `kept`, `pinned` or `settled`, and an optional `snooze` with its wake time and the time it was set. A `pinned` placement carries `kept`, T3's active override, when pinning un-settled the thread. Pins saved without `kept` load with it false. Snapshots saved with the earlier `settlement` field load it as `placement`. The core reports the wake time only while no approval or newer turn result cancels the snooze. The client compares that time with its own clock. The effective settled time is derived when it is read. The core reads `sidebarAutoSettleAfterDays` and each `projectOverrides` entry from `settings.json` when it opens and after every settings save. A missing or invalid value means 3 days, and `null` turns auto-settling off. A save that changes a thread's classification sends a change hint for that thread. Before a pin, settle, snooze, prompt or approval changes a thread, the core stores a due auto-settle as `settled` at the last activity, without the pin or the snooze, as T3's auto-settle command does. `pinned_at_ms` is empty while a pinned thread reads as settled. File-change items carry their `paths`, so a single change shows its file name.

## How parity is checked

A Playwright harness renders T3 v0.0.45 and Z1 in the same headless Chrome at 1440x900 and diffs the screenshots region by region. T3 runs from the server and web client bundled in the installed app, with an isolated `T3CODE_HOME` and a disposable repository. Z1 runs its Vite build against a mocked Tauri IPC that serves the same repository and the same conversation. The harness lives outside the repository. [Verification](verification.md) records the results and the remaining differences.

## PR reviews

Reviews opens from the existing right-panel launcher or add menu, with the R shortcut while the launcher is focused. It is available only for repository checkouts. Threads without a project and removed worktrees have no Reviews control. The list and selected finding share the existing panel width, with long comments and original diff hunks scrolling inside it. Neutral system tokens match Files and Diff.

The compact toolbar shows the PR, a native source-link action, and explicit refresh. Loading, no open PR, no feedback, missing or signed-out `gh`, and failed fetch states remain visible with retry where applicable. A failed refresh hides old actionable findings. Checkout HEAD and PR head are labeled separately. Inline feedback keeps GitHub resolved/outdated status above local triage, and each comment or reply shows its author, source link, original reviewed commit and diff hunk when available. Missing reviewed context says unavailable.

Local intent offers Fix, Dismiss with a required reason, Needs decision, and Clear decision. Saved stale choices retain their reason and saved PR head. Fix means planned work. Saving success appears only after native persistence, and a failure keeps the old saved choice visible with its error. Ask Codex appends the selected finding to an existing conversation draft and explicitly focuses the composer. Existing text stays intact. The button is disabled while the composer cannot accept the draft or submission is pending. The user sends it through the existing composer.
