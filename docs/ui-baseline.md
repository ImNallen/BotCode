# UI baseline

Z1 renders the T3 Code interface for every workflow it implements. The reference is T3 Code v0.0.45 (`pingdotgg/t3code` tag `v0.0.45`, commit `6c8fed35d`), the build in the installed desktop app. T3 Code is MIT licensed. Ported files name their source in a one-line header.

## Styles come from T3, not from a lookalike

`src/t3-theme.css` is T3's `apps/web/src/index.css`, copied verbatim. Regenerate it with `scripts/port-t3-theme.sh <t3code-checkout>`. Tailwind v4 compiles it through `@tailwindcss/vite`, so components use T3's own utility classes and tokens: `bg-sidebar`, `text-secondary-label`, `--chat-max-width`, `alert-glass`. `src/styles.css` imports the theme and holds the only Z1 overrides: root typography, which T3 sets from JavaScript, and the macOS traffic-light inset.

`src/ui/controls.tsx` copies T3's `buttonVariants` and `toggleVariants` tables and the select trigger and item classes. Components copy T3's class strings literally. A hand-written approximation drifts the first time T3 changes a token. A copied class string can only drift when the copy is stale.

## Layout

The shell matches T3's desktop app:

- A 256px left sidebar, resizable from 208px and collapsible with Command+B. It holds the brand row, thread search, T3's project filter, **Add project**, **New thread**, and T3's Pinned section, Active list, Snoozed shelf and Settled shelf across every repository. Pinned threads show as cards at the top, newest pin first. They have no header, because T3 labels them only while dragging. The pin icon on a pinned card unpins it. Active threads show as cards below them, newest activity first. Hovering a card shows a clock button and **Settle** in place of its time, except while an approval waits. The clock opens T3's snooze presets: In 1 hour, In 3 hours, This evening while 6 PM is more than an hour away, Tomorrow at 9 AM, and Next week on Monday at 9 AM. Right-clicking any thread opens T3's thread menu with Pin or Unpin, Settle or Un-settle, and a Snooze submenu with the same presets, or Wake when the thread is snoozed. The **Snoozed** shelf appears above Settled while any thread is snoozed. Its slim rows show the soonest wake first, the time left, such as "2h", and a **Wake thread now** button on hover. It starts collapsed as "Snoozed (n)" and shows only the open thread's row until expanded. A snoozed thread comes back when its wake time passes, without a reload. It comes back early when an approval arrives, or when a turn completes or fails after the snooze. A pinned thread keeps its pin while snoozed and comes back into Pinned. The **Settled** shelf sits at the bottom of the list as slim rows, most recently settled first, with a dimmed badge, the title, the settled age, and an **Un-settle** button on hover. It starts collapsed as "Settled (n)" and shows only the open thread's row until expanded. Expanded, it shows 10 rows and then **Show more** in steps of 25. Both shelves remember their state on this device. Search shows every matching snoozed and settled row. Settling or snoozing the open thread opens the next card, or a new draft in its project when none is left. Command+Shift+S settles or un-settles the open thread in place, and Command+Shift+P pins or unpins it in place. Pinning clears a settle or a snooze. Settling clears a pin or a snooze. Snoozing keeps the pin or settle. A thread settles by itself after its project's auto-settle limit without activity, 3 days by default, unless the user un-settled it or it is snoozed. An idle pinned thread settles by itself too and loses its pin, as in T3. Pinning a settled thread un-settles it, so it stays pinned until its next activity and does not settle by itself before then. A new prompt clears the snooze and returns a settled thread to the active list. It keeps a current pin but does not restore a pin that settling removed. A new approval also returns a settled thread. Z1 leaves out T3's Working shelf, drag and drop, the Custom snooze time, and the Woke indicator. The filter is a searchable popup under the search field. It lists **All projects**, then **No project**, then repositories by name. Choosing a project shows only its threads and its badge replaces the folder icon. The choice persists on this device and falls back to all projects when that project is gone. While a project is chosen, **New thread** opens that project's draft. Each project row has a settings button, and right-clicking the row also opens that project's Project settings page. A fixed bottom bar contains the 32px Settings gear. Settings replaces the sidebar list with search and category navigation, and the bottom bar becomes Back.
- A 52px header with the repository badge, the thread title, T3's Git actions control, and fixed terminal and right-panel toggles.
- A centered 48rem conversation column. The composer floats over the bottom of the timeline. A new thread centers the composer under "What should we build in {repository}?", and that repository name is the repository picker.
- An optional right panel, 540px by default, with Terminal, Files, file, Diff, Pull requests, and pull request tabs. With no tab open, it shows T3's **Open a surface** launcher, where each row's letter opens it: **T** for Terminal, **F** for Files, **D** for Diff and **P** for Pull requests.
- An optional terminal drawer at the bottom of the conversation column. It spans the timeline and composer but not the right panel.

The terminal drawer follows T3's thread terminal drawer and renders with T3's Ghostty terminal. The header's terminal toggle, left of the right-panel toggle, and Command+J open and close it. Opening focuses the terminal, and closing returns focus to the composer. The drawer is 280px tall by default and resizes from its top edge between 180px and 75% of the window. Each thread has its own terminals, and a repository draft has its own. A thread without a project has no toggle until its first message creates its folder. A single terminal shows T3's floating toolbar with **Split Terminal Horizontally**, **Split Terminal Vertically**, **New Terminal** and **Close Terminal**. Two or more terminals show T3's tab sidebar with Single, Side by side and Stacked groups of up to four terminals. Closing a terminal asks for confirmation and stops its process. When the process exits, the terminal prints "[terminal] Process exited" and its tab closes. A terminal that cannot start, such as one in a removed worktree, prints the reason. Switching threads detaches the terminals. Their shells keep running and replay their output when the thread opens again. The open state, height, terminals and splits persist on this device. After a restart, each terminal starts a new shell. Command+K or Control+L clears the terminal. Option and Command with the arrow keys move by word and to the line ends, and Command+Backspace deletes to the line start. Selecting text offers **Copy**, and right-clicking offers **Copy** and **Paste**. On macOS, Option types the character it composes, such as $ or @ on Swedish layouts, as Ghostty does by default, and Command chords other than copy, paste and the terminal shortcuts never reach the shell. Clicking a web link opens it in the system browser. Clicking a path that matches a file in the checkout opens it in the right panel's file tab. A terminal can also open as a right-panel tab from the launcher's **Terminal** row, the **+** menu, or **T** while the launcher shows. A no-project draft shows the row disabled with T3's reason. The tab is titled with its active terminal, such as "Terminal 2", and shows T3's terminal icon. It fills the panel with the same toolbar and tab sidebar as the drawer, holds up to four terminals in one split, and Command+N in it opens another terminal tab. Terminal numbers are shared between the drawer and the panel, so a new terminal takes the lowest free number. Closing the tab asks for confirmation and stops every terminal in it, and closing or exiting its last terminal removes the tab. Each thread keeps its own terminal tabs: switching threads removes them from the panel without stopping their shells, and returning brings them back with replayed output. Only the active tab's terminals stay attached. Text uses T3's terminal font stack at the code font size, with colors from T3's terminal theme variables. Z1 leaves out T3's **Add to chat** and terminal context in the composer, the in-app preview for links, subprocess names in tab labels, hidden drawers kept mounted for recent threads, and terminal history across app restarts.

A thread can also start without a project, as in T3 commit `6b286ae8a`. A launch with no projects opens that draft directly, a repository draft offers **or start without a project** under its heading, and Command+Option+N opens the same draft. That draft asks "What should we work on?" and moves the picker, which reads **No project**, to the line below. Each of these threads runs Codex in its own plain folder under `scratch` in the data directory, named from the date, the first words of the prompt, and a short id. They show T3's gray dashed message icon and have no workspace selector, branch picker, or Diff tab. Z1 creates the **No project** workspace the first time it is needed, and the sidebar's project filter then lists it first. The option is absent when the data directory sits inside a Git work tree. In that case, or when creating the workspace fails, the empty window offers **Add project** instead.

Appearance follows the system by default. The local preferences owner in `src/settings/preferences.tsx` applies the system, light or dark choice, and the prompt and code font sizes. The macOS window keeps an overlay titlebar with native traffic lights at `{16, 28}`. That centers them in the 52px header, level with the sidebar toggle, as T3's Electron position `{16, 19}` does. Elements that carry T3's `drag-region` class also carry `data-tauri-drag-region="deep"`, which gives Tauri the same rule: the subtree drags and clickable children opt out.

## Only working controls appear

T3 shows controls that Z1 cannot back yet: attachments and usage. Z1 leaves them out. The composer has model, reasoning effort, and access-mode menus backed by per-thread Codex settings and the live model catalog. The context strip under the composer starts with T3's workspace selector on a new thread: **Current checkout** or **New worktree**. Once a thread exists, the left side shows a fixed **Local checkout** or **Worktree** label. The right side is T3's branch picker in every state. A worktree draft uses it to choose the base, which defaults to the repository's default branch, and its **Start from origin** switch. The trigger then reads "From origin/{base}" or "From {base}". Elsewhere, picking a ref switches the checkout's branch, and a typed name that matches no ref offers **Create new ref**. Branches checked out in another worktree are disabled. Z1 leaves out T3's pull request badge, pull request checkout, and reuse of another worktree. Sidebar rows of worktree threads show T3's worktree icon and the worktree branch. A new worktree starts with a temporary `z1code/<random>` branch and a matching random folder. Its first accepted message generates a short branch name in the background using the selected Codex model. Z1 applies the name after that turn releases the checkout. The folder stays in place, and the sidebar and branch picker refresh together. Naming keeps the branch the worktree started from as the pull request base. Local checkouts, manually named branches, and later messages do not start naming. A switch, Git action, later message, cleanup, project removal, or provider loss cancels pending naming. Generation errors and existing upstream or remote tracking refs leave the temporary branch in place. A name collision adds the original random suffix without overwriting another branch.

A thread in a repository checkout shows T3's Git actions control at the right of the header. Drafts, threads without a project, and removed worktrees show none. Its quick-action button runs the step T3 picks for the branch, such as **Commit, push & PR**, **Commit & push**, **Push & create PR**, **Create PR**, **Pull**, or **View PR**, and shows only its icon when the header is narrow. The chevron menu lists **Commit**, **Push**, and **Create PR** or **View PR**. A disabled button or item explains itself on hover. An action that commits opens T3's commit dialog first. It shows the branch and the changed files with their line counts, asks for a required commit message, and offers **Cancel** and a button named for the whole action, such as **Commit** or **Commit, push & PR**. Command+Enter starts it. On the default branch, a push or a pull request first asks for confirmation with **Abort** and **Continue**. While the action runs, a toast below the header names the current step. The finished toast shows the result and offers **View PR**, **Push**, or **Create PR** when one applies. When a step fails after an earlier step landed, the toast keeps what landed, such as "Committed abc1234", and names the step that failed. A Codex turn in the same checkout disables the control, and Z1 refuses a prompt or a branch switch there while a Git action runs. Pull requests need the GitHub CLI signed in. Without it, commit and push still work, and the pull request items say what is missing. Z1 leaves out T3's generated commit messages and pull request text, file selection in the commit dialog, **Commit on new branch**, the feature-branch choice in the default-branch confirmation, **Publish repository**, providers other than GitHub and hook output.

The model picker has T3's Favorites and provider rail, with Codex as the current configured provider. Stars save provider and model pairs in device preferences. Favorites survive appearance and font resets. Search hides the rail and searches the live catalog. Model and star buttons are separate grid controls, so starring does not select a model or close the picker.

## Settings

Settings uses T3's compact breadcrumb header, centered page and grouped rows. General and Project open with T3's scope sentence, "Applying settings for", followed by a project picker. The picker lists **All projects**, then **No project** and repositories by name. The URL's `project` parameter holds the choice. Category links keep it, while Command+, and the Settings button open settings for all projects, and leaving settings drops it. Appearance, Keyboard shortcuts and Storage apply to the device and have no sentence. General describes Codex and the conversation access controls, sets where new threads start, whether new worktrees start from origin and when idle threads settle, and restores device preferences. With **All projects** picked, those two rows edit the device defaults. With a repository picked, they read and write that project's override, which the composer uses for that project's new threads. Each row shows T3's layers button, which lists the project and all-projects values and checks the one that applies. T3's reset button appears beside a project override, or beside a device default that differs from the built-in value. **No project** disables both rows, because those threads start in their own folder. The Organization group holds T3's **Auto-settle inactive threads** switch. While it is on, **Days of inactivity before auto-settle** takes a whole number from 1 to 90, and any other entry snaps back when the field loses focus. Both rows share the layers button, which shows a limit such as "1 day" or "Never". This row follows the same project rules, with one difference: it stays enabled for **No project**, because those threads settle too. A project can turn auto-settling off while it stays on elsewhere. Changing the limit moves threads between the active list and the Settled shelf without a restart. Restore defaults appears only for all projects and also clears project overrides. Appearance changes system, light or dark mode and the composer font size from 12 to 20px. The code font size from 11 to 20px applies to code blocks, tool output, file previews, diffs and the terminal. Picking a project adds T3's **Project** item at the top of the navigation. Its page opens with T3's note that the other pages follow the picked project, then the repository's **Name**, the project's **Workspace** override under New threads, and **Remove project** under Danger. As in T3, the auto-settle limit is not on this page. The name saves on Enter or when the field loses focus, and Escape reverts it. **No project** has no name row. Opened without a project, the page asks for one with a button per project. A project that no longer exists reads "Unavailable project" in the sentence, and both pages say it is no longer available in place of its settings. Removal asks for confirmation, then deletes the project entry and all its threads from Z1, as T3's forced project delete does, and returns to the conversation. It leaves the repository, Z1 worktrees and scratch folders on disk and drops the project's overrides. Z1 refuses to remove a project while one of its conversations is running. Z1 recreates **No project** the next time a thread starts without a project. Keyboard shortcuts documents the working sidebar toggle, the shortcut for a thread without a project, the settings shortcut, Escape, the settle and pin shortcuts, and T3's terminal shortcuts. Command+J toggles the terminal drawer from anywhere in the conversation, including the terminal. Command+D splits the focused terminal side by side, Shift+Command+D stacks a new terminal below it, Command+N adds a terminal in a new group, and Command+W closes the focused terminal. These four apply only while a terminal has focus. In a right-panel terminal they act on its tab, and Command+N opens a new terminal tab. While a terminal has focus, Control chords reach the shell, and the thread shortcuts do nothing. Search matches category, section and row labels and focuses the selected setting. It offers only the rows the page shows for the picked project.

Storage follows T3's Storage page and shows its **Worktrees** section with two rows. **Delete inactive worktrees** uses T3's retention control: a days stepper from 1 to 3650 beside a switch. Switching it on sets 8 days, and off shows a muted "Off" in place of the stepper. Typed days apply on Enter or when the field loses focus. **Delete unchanged worktrees** is a switch that removes worktrees with no commits beyond the default branch. Both rules start off and save as `storageCleanup` in `settings.json`, which the Rust runtime reads before every sweep. A missing or invalid value counts as off. The sweep runs once after startup, then hourly, and right after settings are saved. It only removes a Z1 worktree that belongs to exactly one idle thread, is clean with no untracked files, is on the thread's branch, and holds no ignored files other than `node_modules` folders. The inactive rule uses the thread's latest turn start or completion time. The unchanged rule fetches the default branch from origin when the repository has one. Removal runs `git worktree remove` without force and keeps the branch, the thread and its stored path. A removed thread still opens. Its right panel and the line above the composer read "This thread's worktree was removed to save space. Send a message to restore it." The next message recreates the worktree at the same path from the kept branch before Codex starts. If that fails, Z1 refuses the message and shows why. Z1 leaves out T3's **Delete worktrees with deleted threads**, because Z1 cannot delete threads, and **Delete merged worktrees**, because Z1 does not use pull request status to delete worktrees. It also leaves out the **Artifacts and logs** section, because Z1 saves no browser artifacts or rotated logs, and the per-project **Automatic worktree cleanup** override.

Command/Control+, opens settings. Back or Escape returns to the conversation with its draft, thread search, selected thread, panel tabs and scroll retained. An active settings search consumes Escape first. Collapsed sidebars have a Back button in the settings header. Device preferences persist in local storage after schema validation. Storage failures appear in settings while changes continue to apply in memory.

## Domain data the interface needs

T3's timeline reads timestamps that Z1 did not record before this baseline. Each `Turn` now stores `started_at` and `completed_at` in Unix milliseconds. `ThreadSnapshot::stamp_completions` records completion on every save. Turns saved earlier have neither value and show "Worked" instead of "Worked for 8.6s". `ThreadSummary` carries `updated_at` for the sidebar's relative time, `awaiting_approval` for its **Approval** status, and `pinned_at_ms`, `snoozed_until_ms` and `settled_at_ms` for the sidebar sections. Each thread stores a `placement` of `auto`, `kept`, `pinned` or `settled`, and an optional `snooze` with its wake time and the time it was set. A `pinned` placement carries `kept`, T3's active override, when pinning un-settled the thread. Pins saved without `kept` load with it false. Snapshots saved with the earlier `settlement` field load it as `placement`. The core reports the wake time only while no approval or newer turn result cancels the snooze. The client compares that time with its own clock. The effective settled time is derived when it is read. The core reads `sidebarAutoSettleAfterDays` and each `projectOverrides` entry from `settings.json` when it opens and after every settings save. A missing or invalid value means 3 days, and `null` turns auto-settling off. A save that changes a thread's classification sends a change hint for that thread. Before a pin, settle, snooze, prompt or approval changes a thread, the core stores a due auto-settle as `settled` at the last activity, without the pin or the snooze, as T3's auto-settle command does. `pinned_at_ms` is empty while a pinned thread reads as settled. File-change items carry their `paths`, so a single change shows its file name.

## How parity is checked

A Playwright harness renders T3 v0.0.45 and Z1 in the same headless Chrome at 1440x900 and diffs the screenshots region by region. T3 runs from the server and web client bundled in the installed app, with an isolated `T3CODE_HOME` and a disposable repository. Z1 runs its Vite build against a mocked Tauri IPC that serves the same repository and the same conversation. The harness lives outside the repository. [Verification](verification.md) records the results and the remaining differences.

## PR reviews

Open a saved pull request from the Pull requests list to review it in its own right panel tab, titled with its number, such as **#24**. Summary, Timeline and Code use the saved GitHub identity. They remain available after a branch switch or worktree removal. Files and Diff still use the local checkout.

The detail follows T3's pull request view at commit `3e6b450`. The top row shows `owner/repo`, which opens the repository, and the number, which opens the pull request and takes the state color. On the right are the primary lifecycle control and T3's **…** menu. Below them are the title, the author's avatar and login with the relative update time, a copyable `gh pr checkout` command, the base and head branches, and GitHub's own totals of changed files, additions and deletions. Summary, Timeline and Code are a segmented control. On Summary, the checks rollup sits at the right of that row and opens a popover that lists each check with a Details link. Avatars load from `avatars.githubusercontent.com`, which the content security policy allows, and fall back to the login's initial.

Summary lists the reviewers, ringed by their latest outcome, and the labels in their GitHub colors. Both are read-only and read None when empty. A collapsible Description renders the body. When GitHub reports that the signed-in account may update the pull request, hovering the title or the description shows T3's pencil. GitHub allows this on open, closed and merged pull requests. The title edits in place, where Enter saves and Escape cancels. The description opens T3's Write and Preview editor, where Cmd or Ctrl+Enter saves, Escape cancels, and an empty description is allowed. An edit applies after the head moves, but not after the account changes. A saved edit refreshes the detail. A refused or failed save keeps the editor open with its text and shows the reason below it. A collapsible Checks section, closed by default, lists every check and offers Fix check on failed or cancelled ones. The **…** menu holds **All pull requests**, which returns to the list, Refresh, Explain with Codex, Fix findings, every permitted lifecycle action that the header does not already show, and Open on GitHub. Timeline combines opened, commits, comments, reviews, and merged or closed events in newest-first order. Dates that GitHub omits or returns invalid remain unavailable. It keeps original reviewed commits and diff hunks, GitHub resolved/outdated state, review outcomes and source links. Local Fix, Dismiss with a reason, Needs decision and Clear decision preserve their original observation and save through the native owner. Replies and resolve/unresolve appear only when GitHub permits them for the signed-in viewer and exact conversation.

Code renders the remote pull request files with the pierre diff, as T3's Code tab does. Its toolbar shows the file count on the left. On the right are the whitespace, collapse all, stacked or split, line wrap and file tree controls, which share the Diff tab's saved choices. Each file is a collapsible row with its status icon, path and `+a −d`. Files start collapsed, and clicking a row or its chevron toggles it. An expanded file shows line numbers, syntax colors, added and deleted lines, and "N unmodified lines" between hunks. While the signed-in account may review, hovering a line number shows T3's **+** button. It adds a line comment to the review draft and opens it under that line with the cursor in it. Only lines that GitHub returned in the diff accept a comment. A context row in the old column of the split view comments on the same row's new line. Drafted comments stay under their lines and also appear in the review composer, and the trash button discards one. Missing, binary, oversized and truncated patches are listed after the diff with their reason and a GitHub link. Z1 leaves out T3's commit picker, the per-file Viewed checkboxes, multi-line comments, existing conversations under their lines and expanding unchanged context. Failed and limited sections have explicit typed warnings. Successful sections remain visible when another section fails. A failed core read retains the shared last-known status as stale.

The review composer sits at the panel bottom and opens from Review. Session drafts belong to a pull request, account and head. Summary and line comments survive tab and conversation navigation. Comment, Approve and Request changes submit only when explicitly selected and sent. Authors can Comment on their own pull request. A changed head or account requires refresh and an explicit discard of older anchors. Failed or uncertain submissions retain drafts. A confirmed review ID clears only captured revisions that were not edited while submission ran. An uncertain outcome requires checking GitHub and explicit acknowledgment before a new submission.

Ask Codex, Explain with Codex, Fix finding and Fix check append context and any coverage warnings to the conversation draft and focus its composer. Existing text stays intact. The user sends it through the existing Send control. Preparing this text never switches the checkout.

## Linked pull requests

Native Git creation and reuse save the resulting GitHub PR on the originating conversation. The sidebar badge opens the conversation's pull request in the existing right panel. The Git control, its result toast and the panel launcher open it too. With exactly one linked PR they open its detail directly. Otherwise they open the **Pull requests** list. The launcher and the **+** menu offer **Pull requests** only while the conversation links at least one PR. Several conversations can share one PR, and one conversation can retain several PRs. Each list row shows the saved lifecycle, branch names, a working GitHub source link, and **Unlink**. The URL field links an exact GitHub.com PR. Unlinking prevents automatic discovery from restoring that association.

Saved links remain available after a branch switch, restart, or worktree removal. After restart, saved status appears as last known until GitHub confirms it. A failed refresh retains that status and shows the failure. Native reads are shared across conversations and continue with the panel closed. Open PRs on active conversations refresh about once a minute. Closed PRs and PRs linked only to settled conversations refresh about every fifteen minutes. Confirmed merged PRs stop routine polling. Failed reads back off to fifteen minutes. **Refresh** requests a new read and checks the checkout for an unambiguous PR.

Discovery checks the base repository and actual head repository and branch, including a configured upstream base with an origin fork. Native creation and reuse target the origin repository. A PR created against a different base repository can be linked by URL. The former branch-bound Reviews entry has been replaced by linked review detail.

## PR lifecycle

Saved PR detail exposes working lifecycle controls from GitHub permissions and repository policy. The primary action follows the observed state. It offers Resolve conflicts, Ready for review, an allowed merge method, required merge queue or auto-merge in the header, using T3's labels such as **Squash and merge** and **Auto-merge (squash and merge)**. Armed auto-merge shows T3's blue badge with its method, and a queued, merged or closed pull request shows a badge in the same place. The **…** menu includes supported draft, ready, close, reopen, branch update and auto-merge controls. Conflicts keep permitted auto-merge available as a secondary action. GitHub's required queue chooses its merge method.

Every lifecycle mutation opens a confirmation with the captured PR identity, head and account. Auto-merge warns that GitHub may merge immediately. A changed head or account refuses the captured request. Checkout-changing actions also refuse while a linked conversation uses that checkout. Disable auto-merge remains available during agent work.

Accepted queue, armed auto-merge and unavailable confirmation reads stay pending. The conversation stays active until a fresh host observation confirms the outcome. Reconcile reads GitHub without replaying the original mutation. Pending receipts and links survive restart.

An interrupted branch update keeps its outcome unknown. When the same PR is open at another head, Continue from inspected head shows the original method, head and account beside the current head and account. Its explicit confirmation warns that GitHub may still apply the earlier update and continuation does not cancel it. Successful continuation saves the inspected identity while preserving the original request. A fresh same-node merged observation also clears obsolete lifecycle blockers without claiming the earlier uncertain operation succeeded.

Resolve conflicts and Fix findings append captured identity, current unresolved findings, failed checks and coverage warnings to the conversation draft. They include startup failures. They preserve existing text and require the user to Send.

General settings adds Auto-settle merged pull requests independently from Auto-settle inactive threads. Its project override, inheritance indicator and reset follow the existing settings structure. Eligible conversations settle after all linked PRs merge and a merge is recent enough for their trusted activity. New work, kept placement, snooze, approvals and running work protect active conversations. The settled age remains the conversation's activity age.
