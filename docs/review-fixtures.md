# PR review fixture protocol

The executable fixture is `crates/z1-core/tests/fixtures/gh-lifecycle.py`. `Z1_GH_BIN` selects the executable for the native app. State comes from `Z1_PR_FIXTURE_STATE` or a `.json` file beside the executable. Requests append JSON to the state file's `.log` sibling. Verification uses a disposable Git repository and an isolated `Z1_DATA_DIR`.

The default state `{}` describes `fixture/project` PR 41, branch `feature`, head forty `a` characters, and viewer `fixture-viewer`. `repository`, `number`, `branch`, `head`, `viewer`, and `title` override those fields. Review data stays remote when the checkout differs or is removed.

The fixture controls these responses.

| Control                                                                                 | Behavior                                                                                                                                                                                |
| --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mode`                                                                                  | `error`, `slow`, or `hang` affects every request. `delay` sets slow seconds. Hang creates a child that ignores TERM.                                                                    |
| `sectionModes`                                                                          | Maps an operation name, such as `Z1ReviewThreads`, to the same modes.                                                                                                                   |
| `failSections`                                                                          | Names optional operations returning errors. Values are `Z1ReviewThreads`, `Z1ReviewConversation`, `Z1ReviewSummaries`, `Z1ReviewChecks`, `Z1ReviewCommits`, or `files`.                 |
| `failCore`, `failFinal`                                                                 | Fail every core metadata read, or the second and later `Z1ReviewMeta` reads. Reset `metaCalls` to zero between scenarios.                                                               |
| `finalMeta`, `finalViewer`                                                              | Overrides PR fields from the second metadata read. Examples include `state`, `headRefOid`, `id`, `locked`, and terminal timestamps. `finalViewer` changes the final signed-in account.  |
| `wrongIdentitySections`, `crossPrReply`                                                 | Return another PR node in selected optional connections or nested replies. These are fatal identity errors.                                                                             |
| `pages`, `replyPages`, `filePages`                                                      | Exercise outer pagination, nested replies, or full 100-file pages. `pages: 5` exceeds the four-page bound.                                                                              |
| `files`, `missingPatch`                                                                 | Provide exact REST file rows or remove the default patch. Incomplete, missing, binary, or oversized patches have no inline anchors.                                                     |
| `createdAt`, `author`, `lifecycle`, `closedAt`, `mergedAt`                              | Control opened and terminal timeline events. Merge wins when both terminal timestamps exist.                                                                                            |
| `threadAt`, `commentAt`, `reviewAt`, `commits`                                          | Control feedback dates and commit rows. Commits carry `oid`, `messageHeadline`, `committedDate`, and optional `author`. Invalid dates appear unavailable.                               |
| `locked`, `didAuthor`, `canReply`, `canResolve`, `canUnresolve`, `resolved`, `outdated` | Control viewer permissions and thread status.                                                                                                                                           |
| `crossPrThread`                                                                         | Refuses mutation preflight with a thread belonging to another PR.                                                                                                                       |
| `mutation`                                                                              | `refuse` returns GraphQL errors. `uncertain` hangs after dispatch.                                                                                                                      |
| `mutationDelay`, `metaDelay`                                                            | Delay mutation or metadata responses in seconds.                                                                                                                                        |
| `waitFor`                                                                               | Maps operation names to release-file paths. `Z1ReviewConversation:41` holds that read after threads load. `Z1Resolve` holds a resolution mutation. Create the named file to release it. |
| `matchNumber`                                                                           | Uses the GraphQL `number` variable for returned PR identity, so distinct PR reads can run together. Node-only operations use the configured `number`.                                   |
| `failReadAfterReview`                                                                   | Returns an accepted review ID, then fails subsequent reads.                                                                                                                             |

GraphQL requests pin `--hostname github.com` and use named operations. Core and section connections include explicit repository and PR variables. `Z1ReviewReplies` and `Z1ReviewThread` verify returned PR membership. Files use `repos/OWNER/REPO/pulls/NUMBER/files?per_page=100&page=N`.

A successful mutation appends its decoded private input to `state.submitted`. The fixture log includes arguments, PID, working directory, decoded fixture payload, and input-file mode. Production arguments contain only the private pathname. Input files disappear when the command completes.

Metadata counters and mutation state use locked atomic updates, so concurrent fixture processes preserve each other's changes. A `waitFor` process logs its request before waiting and releases when its state file is removed during test cleanup.

The public App tests in `crates/z1-core/tests/reviews.rs` exercise section failures, final identity, shared stale status, chronological timeline, triage restart, protected mutations, exact receipts, refusal, uncertainty, and process cleanup. Cross-conversation tests prove same-PR read and mutation exclusion, receipt replay while busy, coalesced readers, distinct-PR concurrency, and fresh feedback after an applied mutation. The Owner completion test in `crates/z1-core/src/runtime/pr_review/tests.rs` combines process cleanup failure with a denied SQLite receipt update and verifies failure through later shutdown and uncertain recovery after restart. `src/panel/reviews.test.ts` verifies rendered warnings, lifecycle entries, refusal messages, original context, draft revisions, and composer handoffs. Actual Tauri interaction remains a separate gate.
